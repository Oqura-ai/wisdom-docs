A harness is the coding agent Wisdom records. Each has its own adapter; none is central, and
all of them read the same way.

`wisdom doctor` says when an agent is newer than the last tested version. A newer version
usually works, but an agent can change its transcript format.

## Claude Code

- Its hooks are the main evidence; its transcript format is internal, so the copy backs them up.
- A background `/fork` is recorded as its own session and can outlive its terminal.
- A finished background command wakes the agent; that turn shows as `in (harness notice)`.

## Codex

- Codex runs a hook only after you review it in `/hooks`. Until then, sessions are read from
  their own files, marked `not-recorded-live`.
- Its thinking is usually encrypted, and it reports tokens but not cost.
- Calls marked `script step` are Codex's own scripting (`exec`, `wait`); the `Bash` or
  `apply_patch` calls beside them are the real actions.

## Pi

- Recorded through an extension. Inside Pi, `/wisdom-status` reports the session.
- In a tracked home, Wisdom chooses where Pi stores sessions, so `--session-dir` is refused.

## Finding the agent

Wisdom finds `claude`, `codex` and `pi` on your `PATH`, as your shell does. On Windows it
follows npm's `.cmd` shims to the real program. `--claude-bin`, `--codex-bin` and `--pi-entry`
name another installation.
